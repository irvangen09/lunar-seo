# Security Policy

## Supported Versions

| Version | Supported |
|---|---|
| 1.0.x | ✅ |

Only the latest release of the currently active major version receives security patches. See [MAINTENANCE.md](MAINTENANCE.md) for the general version support policy.

## Reporting a Vulnerability

**Do not report security vulnerabilities through public GitHub Issues.** Public issues are visible to everyone before a fix is available, which risks exploitation.

Instead, please report it via:

**GitHub Security Advisories** — open the **Security → Advisories → Report a vulnerability** tab on this repository, once the maintainer has enabled that feature.

Please include the following information to help us respond faster:

- A description of the vulnerability and its potential impact.
- Steps to reproduce (plugin version, WordPress/PHP version, relevant configuration).
- A proof of concept, if possible.

## What to Expect

- Acknowledgement of your report within a reasonable time.
- Ongoing communication about the investigation status and an estimated fix timeline.
- Credit in the Changelog/release notes if you'd like (optional, anonymous credit can also be requested).

Please allow maintainers a reasonable amount of time to ship a fix before publicly disclosing details of the vulnerability (responsible disclosure).
